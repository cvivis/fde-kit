# S1 조사

## 역할
이 스킬은 데이터와 (허용될 때) 외부 자료로 사실·출발선·방안을 조사하고, 사람이 고를 판단 질문을 묶어 보내 결정을 원문으로 받는다.
끝에 설계·로직에 필요한 최소 정보가 모였는지 점검표로 알린다.
사람이 정하는 것: 방안 선택·범위(사용자), 업무 규칙 숫자(담당자), 라운드를 더 할지, 빈칸을 가정으로 넘길지.

## 입력
- `docs/STATE.md` 기준판의 `입력`·`외부 조사`, 과제 요약, `## 입력 목록`. `docs/REQ-TASK.md`(지문 요구 T-ID).
- 대화 입력이 있었으면: `docs/INTERVIEW.md` "정리"의 L1 조건·예외 처리·조건 축(인용 번호만 따라간다).
- 입력 목록의 기획서/RFP·데이터 파일·이미지·`docs/inputs/` 원문.
- 과제 데이터 파일(열 이름·행 수부터 본다). 다시 불렸으면 `docs/RESEARCH.md`의 조사 목록·라운드 기록·결정만.

## 절차
0. **입력에서 요구 도출**: 입력 목록의 지문 밖 입력마다 읽는 방법만 다르게 한다 — 기획서/RFP는 절·문장 단위로, 데이터 파일은 계산 명령으로 센 사실(행·열·결측·값 범위)로,
   이미지·도면은 보이는 것과 추정을 나눠 적는다. 요구는 REQ-USER에 U-ID(출처 `기획서 §절`·`경로 · 시트 · 열`·`이미지 경로 · 영역`, 범위 `미정`)로, 사실은 `## 사실`에 F-ID로.
   숫자 없음·"적절히"·대상 불명·근거 없는 문장은 조사 항목으로 올린다(채울 것). 지어내 채우지 않는다.
1. **조사 목록**: REQ-TASK 행, 0단계의 채울 것, (대화 입력이 있었으면) INTERVIEW 조건·예외를 조사 항목 Q-ID로 만든다. 결정에 바로 쓰이는 항목이 우선 높음.
2. **사실·출발선**: 데이터에서 센 것만 `## 사실`에 F-ID로 적는다 — 근거 칸에 파일·열·실행한 계산 명령, 결과 칸에 출력 그대로.
   기존 방식(지금 하는 방식·단순 규칙)의 결과를 `## 출발선`에 잰다. 성공 기준 숫자와 VERIFY 전/후 비교의 기준이 된다.
3. **외부 사례**: STATE `외부 조사: 가능`일 때만 실제로 연 출처를 E-ID로 적는다(제목·발행처·날짜·주소·요지·우리에게 쓰는 점).
   `불가`면 표에 `없음 — 외부 조사 불가` 한 줄만 둔다. 모델 일반 지식은 사실 표 밖에 `- 일반 지식 — 검증 안 됨: …`으로 적는다.
4. **방안 비교**: 방안 2~3개를 표로(무엇을 하나·장점·약점·근거 F/E ID·구현 시간·위험), `- 추천: <방안> — <이유>` 한 줄.
5. **라운드**: 요약(근거 ID) + 방안 비교 + 판단 질문 2~3개(받는 사람: 담당자 = 업무 규칙 / 사용자 = 해법·범위)를 **한 번에 보내고 멈춘다**.
   라운드 수 상한은 없다 — 사람이 끝내자고 할 때까지 돈다. 사람은 제시된 조사를 검수하고 판단한다(AI가 판단을 대신하지 않는다). 받은 답은 `## 라운드 기록`에 원문 그대로, 답·되물음에서 나온
   새 항목은 조사 목록에 Q-ID(파생 출처 = 라운드 n)로 붙인다. 사람이 정한 것은 `## 결정`에 C-ID(누가·원문·옮긴 요구)로 남기고
   `docs/REQ-USER.md`에 U-ID(출처 C-ID, 범위 `미정`)로 올린 뒤 `bash .agents/skills/fde-start/scripts/check-req.sh count`.
6. **최소 정보 점검**: 수집을 끝내기 전에 `## 최소 정보 점검` 8칸을 채움(근거)/빈칸/가정(사람 말)으로 채우고 `- 판정:` 줄을 쓴다.
   빈칸이 있으면 끝내지 않고 **빈칸만 묶어** 한 번에 묻는다. 사람이 "가정으로 넘겨"라고 하면 가정으로 적고 넘어간다.
7. 사람이 끝내자고 하면 남은 항목은 상태 `보류`로 두고 DEFENSE·한계로 넘긴다.

## 출력
```text
파일: docs/RESEARCH.md — 조사 목록(Q-ID) / 사실(F-ID · 근거 명령 · 결과) / 외부 사례(E-ID 또는 "없음 — 외부 조사 불가") / 출발선 / 방안 비교 + 추천 / 라운드 기록 / 결정(C-ID) / 최소 정보 점검 8칸 + 판정
      docs/REQ-USER.md — 결정에서 옮긴 U-ID(출처 C-ID, 범위 미정), 개수 줄은 check-req.sh count가 고침
라운드 보고 (매 라운드, 그리고 멈춤):
라운드 <n> · 남은 조사 항목 <개수>
요약: <찾은 것 2~4줄, 줄마다 F·E ID>
방안: <방안 표 요약> / 추천: <방안> — <이유>
판단 질문:
1. <질문> (받는 사람: 사용자|담당자)
2. <질문> (받는 사람: …)
[3. …]
마지막 보고: 최소 정보: <충족 | 미충족 — 빈칸: 칸 이름 목록> / 요구: <check-req.sh count 출력 한 줄> / 다음: $fde-agreement
```
불변 조건: 판단 질문은 라운드마다 2~3개이고 받는 사람이 적혀 있다. 사실 행마다 근거에 계산 명령이 있다. 외부 사례 행마다 주소가 있고, 외부 조사 불가면 외부 사례는 0행이다.
결정 행의 원문은 사람의 말 그대로다. 최소 정보 점검은 정확히 8칸이고, 빈칸이 하나라도 있으면 판정은 `미충족`이다.

## 원칙
1. 업무 규칙 숫자(한도·시각·예외 기준)는 담당자 답으로만 확정한다 — 조사로 대신하지 않는다. 해법·범위 선택은 사용자에게 묻는다.
2. 데이터가 말하는 것(사실)과 내 추천(해석)을 나눈다. 추천은 방안 비교 아래 한 줄뿐이다.
3. 질문은 묶어서 한 번에 보낸다. 사람이 답하기 전에 다음 라운드를 시작하지 않는다.
4. 뒤 단계(S3~S5)에서 다시 불리면 조사만 하고, 결과가 범위·설계·승인된 작업 목록을 바꾸면 결정 행으로 올려 사람 승인을 먼저 받는다.

## 금지사항
- 숫자·출처·논문 제목·회사 사례를 지어내지 않는다. 실행하지 않은 계산 결과를 사실 표에 쓰지 않는다.
- 외부 조사 불가인데 웹을 찾거나 외부 사례를 만들지 않는다.
- 담당자·사용자의 답을 지어내 결정 표를 채우지 않는다. 방안을 대신 고르지 않는다.
- 코드·앱 파일을 만들지 않는다(계산용 일회성 명령은 된다 — 명령은 근거 칸에 남긴다).

## 확인요청
- STATE `입력`·`외부 조사`가 비어 있으면 조사 전에 사람에게 묻는다.
- 같은 판단을 담당자와 사용자 중 누가 정할지 애매하면 받는 사람을 둘 다 적지 말고 사용자에게 먼저 묻는다.
- 같은 항목이 두 라운드 넘게 결정이 안 났으면 "한 라운드 더 / 추천안으로 결정 / 가정으로 넘김"을 묻는다.

## 예시
### 입력
```
STATE: 입력: 지문 1 · 데이터 파일 1 / 외부 조사: 불가
REQ-TASK T-01: "희망도서 신청 중 이번 달 구입할 목록을 예산 안에서 정해 CSV로 제출한다"
데이터: data/requests.csv (신청일, 분야, 가격, 신청자수)
```
### 출력
```text
RESEARCH 사실: | F-01 | 신청 412건, 가격 합계 9,870,000원 | requests.csv 가격 열 · awk -F, 'NR>1{s+=$3}END{print NR-1, s}' data/requests.csv | 412 9870000 |
RESEARCH 출발선: | 신청 순서대로 예산까지 고른 권수 | 131권 | sort -t, -k1 … (명령 그대로) |
라운드 1 · 남은 조사 항목 3
요약: 신청 412건 가격 합계가 예산의 약 3배다(F-01). 신청 순서로 고르면 131권(출발선).
방안: A 신청자수 많은 순 / B 분야별 고르게 / 추천: A — 데이터로 바로 계산되고 설명이 쉽다(F-01)
판단 질문:
1. 같은 책을 여러 명이 신청했으면 한 권으로 셀까요, 신청자수만큼 가중할까요? (받는 사람: 사용자)
2. 분야마다 최소 몇 권은 꼭 넣어야 하나요? (받는 사람: 사용자)
```

## 인접 스킬
- vs `$fde-interview`: 인터뷰는 담당자의 말(L1·L2·L3·예외 처리)을 모으고, 이 스킬은 데이터·자료로 사실·방안을 조사하고 판단을 받는다. 대화 입력이 없으면 인터뷰 없이 이 스킬부터 한다.
- 다음: `$fde-agreement`가 RESEARCH `## 결정`과 REQ-USER로 범위를 확정한다.

## 완료
- 최소 정보 판정이 `충족`이거나 사람이 빈칸을 가정으로 넘겼다. 사람이 조사를 끝내자고 하면 남은 조사 항목은 보류로,
  빈칸은 사람에게 묻고 답을 받은 만큼만 반영한 채 판정을 그대로 적는다(지어내 채우지 않는다). 커밋 `[S1] docs: 조사 정리`.
- 단계 종료 때 STATE 진행 측정에 시각·확인 가능한 토큰을 한 행 남긴다.
- 자가 검증: 사실 행마다 근거 칸에 명령이 있고, 결정 행마다 원문이 있고 REQ-USER에 같은 C-ID를 출처로 한 U-ID가 있다. 최소 정보 8칸에 빈 상태가 없고
  `check-req.sh count`가 exit 0이다.
