# S2 합의 (혼합형 36–42분 · 리서치형 28–40분)

## 역할
이 스킬은 인터뷰·조사 결정을 이후 모든 작업의 기준이 될 합의문으로 좁히고, 담당자에게 보낼 문장을 채운다.
사람이 정하는 것: 범위 확정, 방안 결정(사용자), 사각지대 후보 채택/기각, 메시지 문장 수정과 발송.

## 입력
`docs/INTERVIEW.md`의 "정리"·"요구 체크리스트"와 근거에 해당하는 대화 행만(리서치형은 INTERVIEW가 비어 있다 — 읽지 않는다).
`docs/RESEARCH.md`의 `## 방안 비교`·`## 결정`·`## 최소 정보 점검`, `docs/REQ-TASK.md`·`docs/REQ-USER.md` 표.
STATE 기준판 `과제 유형`. 메시지가 필요할 때 `references/messages.md`의 해당 절만.

### 과제 유형별 경로
| | 혼합형 | 리서치형 |
|---|---|---|
| 한 줄 명세 [어떤 문제] 근거 | INTERVIEW "목표(왜)" 인용 `#n` | 지문 원문(T-ID) + 사용자 결정 C-ID |
| 방안 결정 | 사용자에게 묻고 RESEARCH `## 결정`에 C-ID(누가: 사용자) | 같음 |
| 담당자 합의 확인(템플릿 1) | 보낸다 | 없음 — "팀장 확인"에 `해당 없음 — 리서치형, 결정 C-ID 참조` |
| `$fde-blindspot` Cycle 1 | 한다 | 한다 |

## 절차
0. **결정 기록**: RESEARCH에서 아직 사용자가 고르지 않은 방안·범위 판단이 있으면 묶어서 한 번에 묻는다. 답은 원문 그대로
   RESEARCH `## 결정`에 C-ID(결정·누가·원문·옮긴 요구)로 남기고, 결정에서 나온 요구는 REQ-USER에 U-ID(출처 C-ID)로 올린다.
   **REQ-USER 범위 확정**: `미정`인 행마다 `이번` 또는 `제외 — 이유`로 정하고(만들 것 ≤3·시간 기준) `check-req.sh count`를 다시 돌린다.
1. `docs/AGREEMENT.md`를 양식대로 채운다.
   - 맨 위 **한 줄 명세**: "[누가] [언제] [무엇을] 할 수 있게 해서 [어떤 문제]를 줄인다." 바로 아래 `- 근거:` 줄에
     혼합형은 INTERVIEW "목표(왜)" 인용 `#n`, 리서치형은 결정 C-ID + 지문 T-ID를 적는다(`check-stage.sh S3`가 리서치형 C-ID를 확인한다).
     근거가 비어 [어떤 문제]를 문장으로 못 쓰면 **채워 넣지 말고 멈춰 사용자에게 알린다**(혼합형은 그 질문을 확인 메시지에 넣는다).
   - **만들 것 3개 이하**, 각 항목에 근거 — INTERVIEW 인용 `#n`, 또는 T-/U-/C- ID. 성공 기준 행마다 근거 열에 T-/U-/C- ID.
   - **이번에 안 만들 것**: 담당자가 원했지만 뺀 것과 이유. INTERVIEW "상쇄" 인용이 있으면 그것이 첫 근거, 없으면 시간·위험.
   - **제약**: INTERVIEW "제약·경계" 인용(하면 안 되는 것, 기기·환경). S3가 이것을 어기는 구조를 내지 않게 한다.
   - **성공 기준**: 담당자가 화면을 보고 바로 판단할 수 있는 문장, INTERVIEW "성공 판단" 인용 우선. "확인 방법" 열은 비워 둔다(S3에서 채운다).
     **개수 상한은 5개**(기본, 만들 것 개수에 맞춰 조정 가능). 합의 뒤 추가 요구가 들어와 기준을 늘리려 하면,
     늘리기 전에 멈추고 ① 이번 성공 기준은 그대로 두고 **다음 사이클 희망**으로 넘기거나 ② 기존 기준·만들 것 중 하나와
     **교체**할지 사람에게 묻는다. 어느 쪽을 골랐는지 AGREEMENT "변경 이력"에 한 줄로 남긴다.
   - **가정**: 확인 못 한 것. S1에서 넘어온 빈 층·빈 요구 칸 포함.
     INTERVIEW "요구 체크리스트"의 **빈 칸은 그 줄의 [기본] 값으로 채우고 `— 가정`을 붙인다**(INTERVIEW 그 줄에도). AGREEMENT 가정에는
     칸 ID와 함께 한 줄씩: `E2 저장 기간: 이 브라우저 — 가정, 담당자 미확인`. 시간 때문에 못 물은 칸이라도 멈추지 않는다.
     설계에 영향이 큰 가정(저장·공유·기기) 1~2개는 확인 메시지의 "빠지면 안 되는 게 있으면" 줄 앞에 "제가 ○○로 가정했어요"로 넣는다(접촉 횟수는 그대로).
   - 남은 작업 시간(제출 시작 170분까지 약 2시간 10분 — 혼합형 42분·리서치형 40분 종료 기준)에 끝낼 수 있는 범위로 좁힌다.
2. 1단계 초안이 나오면 `$fde-blindspot`을 호출해 Cycle 1 사각지대 점검(6행)을 받는다. 채택된 것만 만들 것/안 만들 것/가정에 반영한다.
3. (혼합형) 확인 메시지를 **현업 언어로(기술 용어 없이) 5줄 이내**로 쓴다 → `references/messages.md` 템플릿 1. 리서치형은 건너뛴다.
4. `docs/STATE.md` 기준판 "목표 한 줄"을 한 줄 명세로 바꾼다. 합의 항목·가정은 항목당 한 줄로 적고,
   인용은 근거 번호와 필요한 원문만 둔다. 이미 확정된 문구를 매 호출 다시 생성하지 않는다.
5. 범위·사각지대 채택/기각·합의 문안의 전달 여부를 한 번에 묻는다. 이미 받은 답은 재질문하지 않는다.

### 담당자 접촉 리듬 — 4회가 상한
| 시점 | 보내는 것 | 남는 곳 |
|---|---|---|
| S2 직후 | 합의 확인 (템플릿 1) | AGREEMENT "팀장 확인" |
| S4 중반, E2E가 막 동작한 직후 | **중간 보고** (템플릿 2) | 대화 기록 + 방향 수정 |
| S6 직후 | **결과 보고 → 수용 확인** (템플릿 5 → 6) | AGREEMENT "수용 확인" |

- **S3 직후 1회만 예외** — 담당자의 기준·순서를 구현에 옮긴 직후 되읽어 확인한다(템플릿 1-B).
- 추가 요구가 오면 템플릿 3, 한 기능이 막히면 템플릿 4. 그 외에는 늘리지 않는다.
- 보낸 뒤 **답을 기다리지 않고 다음 항목을 시작한다.**
- 이후 단계에서: 템플릿 3을 보냈으면 같은 자리에서 "이번에 안 만들 것"에 항목과 이유(메시지와 기록이 한 쌍).
  템플릿 4의 답이 오면 DECISIONS에 "담당자 동의" 한 줄. 끝까지 답이 없으면 "수용 확인"에 **요청했으나 응답을 받지 못함**.

## 출력
```text
파일: docs/AGREEMENT.md — 한 줄 명세 + 근거 / 만들 것(# · 기능 · 근거 인용·ID) ≤3 / 안 만들 것(항목 · 이유) / 제약 / 성공 기준(# · 기준 · 확인 방법=empty · 근거 ID) / 가정 / 사각지대 점검(Cycle 1, $fde-blindspot 출력) / 팀장 확인
      docs/RESEARCH.md ## 결정 — 사용자·담당자 결정 C-ID(원문 그대로) / docs/REQ-USER.md — 범위 확정(이번|제외 — 이유), 개수 줄은 check-req.sh count
메시지: 혼합형만 — 템플릿 1을 채운 5줄 이내 초안 (사람이 보낸다)
보고: 요구: <check-req.sh count 출력 한 줄> / 결정: <C-ID 목록> / 범위 미정: <0건이어야 함>
```
불변 조건: 만들 것은 1~3개, 각 행에 근거(INTERVIEW 인용 또는 T-/U-/C- ID)가 있다. S2가 끝나면 REQ-USER에 범위 `미정`이 없다. 결정 행의 원문은 사람의 말 그대로다. S2가 끝나면 INTERVIEW 요구 체크리스트에 빈 칸이 없다(인용·지문·가정 중 하나). 한 줄 명세의 [어떤 문제]는 INTERVIEW 인용(리서치형은 결정 C-ID + 지문)에 근거하거나, 근거가 없다는 사실이 가정에 있다.
사각지대 Cycle 1의 6행 모두 채택/기각이 사람 답으로 찬다. 확인 방법 열은 S2에서 비어 있다.

## 원칙
1. 범위는 시간으로 자른다. 자른 것은 "안 만들 것"에 이유와 함께 남긴다.
2. 성공 기준은 담당자의 말로 쓴다(INTERVIEW 인용을 우선).

## 금지사항
- 근거(INTERVIEW 인용 또는 T-/U-/C- ID)가 없는 만들 것을 넣지 않는다.
- 담당자 답을 지어내 "팀장 확인"을 채우지 않는다. 사용자 결정을 지어내 RESEARCH `## 결정`을 채우지 않는다. 메시지를 대신 보내지 않는다.

## 확인요청
- 만들 것이 3개를 넘으면 무엇을 뺄지 묻는다.
- 성공 기준을 5개 넘게 늘리라는 요청(직접 지시든 추가 요구 반영이든)이 오면, 늘리기 전에 멈추고 다음 사이클로 미룰지
  기존 것과 교체할지 묻는다 — "기준 하나 더 넣어 줘"에도 바로 늘리지 않는다.
- 한 줄 명세의 [어떤 문제]를 INTERVIEW 인용(리서치형은 결정 C-ID + 지문)으로 못 쓰면 멈추고 사용자에게 알린다 — 목적을 문장으로 못 쓰면 S3를 시작하지 않는다.
- 혼합형: S2를 끝내기 전, 합의 확인 메시지를 실제로 보냈는지 묻는다. 안 보냈으면 "아직 전달 전"을 적고 STATE "막힌 것"에도 남긴다.
- RESEARCH 최소 정보 판정이 `미충족`이면 빈칸만 묶어 묻는다 — 가정으로 넘기라는 답을 받기 전에는 S3로 넘기지 않는다(`check-stage.sh S3`가 막는다).

## 예시
### 입력
```
INTERVIEW 정리 — 목표(왜): "제가 매번 옆에 못 있어 주니까 선수들이 연습을 혼자 하다 그냥 끝내요."
상쇄: "기록 보는 건 나중이어도 돼요. 일단 답하고 바로 돌아보는 게 먼저예요."
제약·경계: "선수 이름이 남는 건 안 돼요."
```
### 출력
```text
한 줄 명세: 선수가 혼자 인터뷰 연습을 할 때 답한 직후 팀장 방식으로 돌아볼 수 있게 해서, 혼자 하다 그냥 끝나는 연습을 줄인다.
안 만들 것: | 지난 기록 모아 보기 | 담당자 상쇄 — "기록 보는 건 나중이어도 돼요" |
제약: - 결과·기록에 선수 이름을 저장하지 않는다 — "선수 이름이 남는 건 안 돼요."
```

## 인접 스킬
- vs `$fde-interview`·`$fde-research`: 인터뷰는 말을 모으고 조사는 사실·방안을 모으며, 이 스킬은 결정을 기록하고 무엇을 만들지 자른다.
- vs `$fde-blindspot`: 이 스킬은 말해진 것을 자르고, blindspot은 말해지지 않은 것을 점검한다. 2단계에서 호출.
- 다음: `$fde-design`이 AGREEMENT 범위와 번역표로 설계한다.

## 완료
- 만들 것 ≤3(각 근거), 안 만들 것, 성공 기준(≤5), 가정이 찼고, `$fde-blindspot` Cycle 1이 끝났고, REQ-USER에 범위 `미정`이 없고,
  (혼합형) 메시지를 사람이 보냈다. 답을 기다리지 않고 S3로. 담당자 답을 "팀장 확인"에 그대로 붙이면 커밋 `[S2] docs: 현업 합의문`.
  리서치형은 "팀장 확인"에 `해당 없음 — 리서치형, 결정 C-ID 참조`를 적는다.
  **"팀장 확인"을 양식 placeholder(`(팀장 답변 그대로)`) 그대로 두고 넘어가지 않는다** — 사람에게 "메시지를 보냈는지" 묻고,
  보냈으면 받은 답 또는 "요청했으나 아직 응답 없음"을, 안 보냈으면 "아직 전달 전 — 사람이 전달 필요"를 적는다.
- S3까지 진행하라는 지시를 이미 받았고 범위가 확정됐으면 `$fde-design`으로 이어 간다. 별도 "다음 단계" 확인은 요구하지 않는다.
- 단계 종료 때 STATE 진행 측정에 시각·확인 가능한 토큰을 한 행 남긴다.
- 자가 검증: AGREEMENT 만들 것 행마다 INTERVIEW에 같은 인용이 있거나 그 ID가 REQ-TASK·REQ-USER·RESEARCH 결정에 있고, STATE 목표 한 줄 = 한 줄 명세, 성공 기준 수 ≤5(넘으면 변경 이력에
  다음 사이클/교체 판단이 있고), "팀장 확인"에 placeholder가 남아 있지 않다. `check-req.sh count`가 exit 0이고 범위 미정 경고가 없다.
