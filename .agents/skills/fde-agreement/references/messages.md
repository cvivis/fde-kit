# 담당자 메시지 템플릿 6종

사람이 업무 메신저에서 직접 보내는 문장이다. 에이전트는 이 문장을 채워 주기만 하고 보내지 않는다.

- **기술 용어 금지.** 모델·스키마·엔드포인트·배포 같은 말을 쓰지 않는다.
- **5줄 이내.** 대화창은 줄바꿈이 그대로 전송되는 경우가 있어 긴 문장은 잘려 나간다.
- `○○`(이번 과제의 대상) `△△`(담당자가 쓴 표현·남겨 둘 것) `××`(빼는 후보)만 바꿔 **그대로 복사**한다.
- 1~2 단어는 과제 맥락으로 바꿔도 되지만 **구조는 바꾸지 않는다**. 점수를 만드는 것은 구조다.

## 접촉 리듬 — 4회가 상한

| # | 시점 | 템플릿 | 받아내는 것 |
|---|---|---|---|
| 1 | S1 (발굴) | 질문 뼈대 (`fde-interview/references/expertise-extraction.md`) | L1·L2·L3 |
| 2 | S2 직후 | **1 합의 확인** | 범위 동의 → AGREEMENT "팀장 확인" |
| 3 | S4 중반, E2E가 막 동작한 직후 | **2 중간 보고** | 방향 수정 기회 |
| 4 | S6 직후 | **5 결과 보고** → **6 수용 확인** | AGREEMENT "수용 확인" |

**3·4번이 비어 있으면 혼자 만들고 끝에 들고 간 기록이 된다.** 중간 보고 한 번의 비용은 40초고,
담당자가 방향을 틀 때 S4 중반에 아는 것이 마감 직전에 아는 것보다 훨씬 싸다. 보내고 나서
답을 기다리지 않고 다음 항목을 시작한다 — 왕복 지연이 비용이 되지 않는다.

템플릿 3·4는 **일이 생길 때만** 쓴다. 상한을 넘기지 않는 유일한 예외는 아래 1-B다.

## 1. 합의 확인 (S2)

```
말씀해 주신 내용을 이렇게 정리했습니다.
1) ○○
2) △△
이번에는 ××는 빼고 위 두 가지를 확실히 되게 만들겠습니다. 이 방향이 맞을까요?
빠지면 안 되는 게 있으면 지금 말씀해 주세요.
```

답을 AGREEMENT **"팀장 확인"**에 그대로 붙인다. 고쳐 쓰지 않는다.

### 1-B. 기준 확인 (조건부 — S3 직후)

담당자가 말한 **기준·순서를 구현에 옮긴 직후** 한 번 되읽어 준다. 접촉을 5회로 늘리는 유일한 예외다.

```
말씀해 주신 걸 이렇게 정리했는데 맞을까요?
- 먼저 보시는 건 ○○, 그다음이 △△
- 의견은 좋았던 것 먼저, 고칠 건 하나만
제가 잘못 이해한 게 있으면 알려주세요.
```

**기준을 잘못 이해하면 S4 전체가 틀린 방향으로 간다.** 40초로 그 리스크를 막는다.

## 2. 중간 보고 (S4 중반)

```
말씀해 주신 것 중 두 가지를 먼저 동작하게 만들었습니다.
1) ○○까지는 지금 바로 보실 수 있습니다.
2) 말씀하신 "△△" 표현을 그대로 기준으로 쓰고 있습니다.
남은 시간에는 ××를 다듬을 예정입니다.
지금 방향에서 바꾸고 싶은 게 있으실까요?
```

2)번에 **담당자가 한 말을 그대로 되돌려 인용**한다. 자기 말이 들어갔다는 것을 확인하면
"내 방식이 담겼나"를 담당자 본인이 판정해 준다. 타이밍은 **보여줄 것이 있고 아직 고칠 시간이
남은 지점** — 첫 화면이 끝까지 동작한 직후가 최적이다.

## 3. 범위 추가 요청 거절·연기

```
좋은 의견 감사합니다. 그 부분은 지금 넣으면 ○○가 불안정해질 것 같습니다.
이번에는 빼고, 어떤 점이 필요하신지만 기록해 두겠습니다.
대신 지금 하고 있는 △△를 확실하게 되는 상태로 마무리하겠습니다.
괜찮으실까요?
```

핵심은 **"기록해 두겠습니다"**다. 거절이 아니라 처리다. 그리고 거짓이 아니어야 한다 —
보낸 직후 AGREEMENT **"이번에 안 만들 것"**에 항목과 이유를 적는다. 메시지와 기록이 한 쌍이다.

## 4. 막힌 것 알리기 + 선택지

**선택지 2개 + 내 추천**이 형식이다. 셋 중 하나라도 빠지면 보내지 않는다.

```
○○ 부분에서 예상보다 시간이 걸리고 있습니다. 두 가지 중에 골라 주시면 좋겠습니다.
(가) ○○는 간단한 형태로만 두고 △△를 마무리하기
(나) ○○를 제대로 하고 △△는 다음으로 넘기기
저는 (가)가 남은 시간에 더 안전해 보입니다.
어떻게 생각하세요?
```

- **"어떻게 할까요?"만 보내면 안 된다.** 판단을 담당자에게 넘기는 것이고 감점이다.
- 추천을 붙이면 **판단은 내가 하고 승인만 받는** 구조가 된다.
- 답이 늦으면 추천대로 진행한다. 답이 오면 `docs/DECISIONS.md`에 "담당자 동의" 한 줄을 더한다.

## 5. 결과 보고 + 시연 안내 (S6 직후)

```
말씀해 주신 내용을 반영해서 이렇게 만들었습니다.
주소를 열고 "○○" 를 누르시면 바로 결과 화면이 보입니다.
직접 해보시려면 △△를 넣고 한 번 더 눌러 주세요.
(△△가 어려우면 화면 아래 칸에 붙여넣기도 됩니다)
보시고 어색한 부분이 있으면 알려주세요.
```

**시연 3스텝을 현업 언어로 옮긴 것**이다. 시연 문서와 같은 재료를 쓰고, 문장만 바꾼다.
2번째 줄은 **아무 설명 없이 눌러서 결과가 나오는 경로**여야 한다. 4번째 줄의 대체 경로를 빼지 않는다.

## 6. 수용 확인 요청 (5번 직후 연달아)

```
지금 상태로 ○○님 업무에 쓸 수 있을 것 같은지, 아니면 꼭 더 필요한 게 있는지
한 줄만 남겨주실 수 있을까요?
남은 시간에 반영하거나, 못 하면 한계로 적어두겠습니다.
```

**이 답이 AGREEMENT "수용 확인" 칸에 들어가는 문장이다.** 받은 그대로 붙인다 —
요약·윤문하면 현업의 승인 문장이 아니라 내 문장이 된다. 더 필요한 것을 받았으면
반영하거나 `docs/VERIFY.md`의 알려진 한계에 적는다.

## 답이 오지 않을 때

비워 두지 않는다. AGREEMENT "수용 확인"에 **시도한 기록**을 적는다.

```
> 결과 보고와 수용 확인을 요청했으나 응답을 받지 못함(대화 기록에 남아 있음).
> 요청 내용: 지금 상태로 업무에 쓸 수 있는지 / 꼭 더 필요한 것이 있는지
```

빈 칸은 "안 물어봤다"로 읽히고, 이 두 줄은 "물어봤고 답이 오지 않았다"로 읽힌다. 전혀 다르다.

## 보내지 않는 문장

| 보내지 않는다 | 대신 |
|---|---|
| "어떻게 할까요?" | 템플릿 4 (선택지 2개 + 추천) |
| "그건 어려울 것 같습니다" | 템플릿 3 (빼는 이유 + 기록해 두겠습니다) |
| "어떤 식으로 만들면 될까요?" | "방법은 제가 찾아보겠습니다. '이건 됐다' 싶은 상태만 알려주세요" |
| 기술 용어가 들어간 문장 | 담당자가 화면에서 보는 것으로 바꿔 쓴다 |
| 답을 기다리며 작업을 멈추는 것 | 보내고 바로 다음 항목을 시작한다 |
