# S7 정리·제출 (148–170분, 170–180분 제출 절차)

## 역할
이 스킬은 제출물이 판단과 근거, 검증 결과, 남은 한계를 담도록 정리한다. 제출 문서는 AI와 함께 써도 불이익이 없다.
제출 후 서술형(제출 확정 후 약 5분 대기, 6문항×5분)은 AI·복붙 금지, 사람이 직접 타이핑한다 — 그래서 정리는 160분까지, 160–170분은 사람의 답 연습 시간.
사람이 정하는 것: 의도 칸 문장, 지울 파일, 답 연습, 제출 확정.

## 입력
코드, `docs/*`, `git log`, 과제 README의 필수 제출물 목록(STATE 과제 요약).

## 절차
0. `$fde-blindspot`을 호출해 Cycle 2(완결성 점검, VERIFY·실제 코드 근거)를 받는다. 채택된 것은 DECISIONS "알려진 한계"에,
   필요하면 DEFENSE 질문 재료로. 왕복이 늦어지면 생략하고 "확인 못 함"으로 제출 문서 "알려진 한계"에 적는다.
0-B. `bash .agents/skills/fde-start/scripts/check-stage.sh S7`로 과제 원본 파일이 그대로인지 본다. 바뀌었으면 `git checkout -- <파일>`로
   되돌리고 그 내용을 복사본으로 옮긴 뒤 진행한다. 출력의 "구현 확인: … 미확인: …" 줄(`check-req.sh verify`)의 미확인·미충족 요구 ID와
   VERIFY "해석 점검"에서 사람이 "그대로 둠"으로 정한 행을 제출 문서 "알려진 한계"에 옮긴다(미확인을 빼거나 충족으로 바꾸지 않는다).
1. **문서명부터 STATE "필수 제출물"을 본다** — S0에서 과제 README를 읽고 적어 둔 그 목록이 기준이다. **과제 원본 파일은 고치지 않는다**
   (AGENTS.md 원칙 11 — README도 데이터도). 제출물이 원본 파일이면 STATE "제출 복사본"의 `submission/<같은 경로>`에 쓴다
   (없으면 `cp <원본> submission/<같은 경로>`로 만들고 STATE에 적는다). 과제가 새 파일 이름만 정했으면 그 이름으로 새로 만들고,
   이름도 정하지 않았으면 `SUBMISSION.md`를 만든다. 내용: 무엇을 해결하나(현업 언어 2줄) / 실행 방법(명령 그대로, 포트) / 화면 흐름 / 합의 범위와 제외한 것과 이유 / 검증 결과 요약 / 알려진 한계
2. DECISIONS에 빠진 결정이 있으면 코드·커밋 로그를 보고 채운다. **의도** 칸은 코드에서 추론하지 않는다 — 빈 결정 번호를 모아 한 번에 묻는다.
2-B. STATE "필수 제출물"에 **AI 활용 회고 문서**("가장 어려웠던 것", "막혔을 때 어떻게 접근했나" 같은)가 있으면 채운다.
   사실(시각·증상·한 일·결과)은 "어려움·접근 기록"·실패 기록·VERIFY·git log에서만 가져오고, 느낌·판단은 사람 말 그대로 인용한다.
   사람 말이 없는 질문은 한 번에 모아 묻는다. 지어낸 소감을 쓰지 않는다. 중간 점검 문서가 비어 있으면 같은 방법으로 채운다.
3. 점검 목록만 보고(삭제는 사람 확인 후): 디버그 출력, 안 쓰는 파일, 비밀값 흔적, 필수 제출 파일 누락.
4. `docs/DEFENSE.md`에 서술형 예상 질문 6개를 **질문만**: "왜 X를 이렇게 했나", "Y가 실패하면 어떻게 되나", "Z를 개선하려면 무엇부터".
5. 서버는 실행 중인 상태로 둔다.
6. **원복 안내**: STATE "제출 복사본"이 있으면 완료 보고 맨 위 "사람이 할 일"에, 제출 절차(170분) 전에 사람이 직접 칠 복사 명령을
   복사본마다 한 줄씩 적는다 — `cp submission/README.md README.md`. 복사 뒤에는 `check-stage.sh`가 원본 변경으로 막는 것이 정상이라는 것도 적는다.
   복사는 사람이 한다(원칙 11). 복사본이 없으면 "원복할 것 없음"이라고 적는다.

## 출력
```text
파일: 제출 문서(submission/ 복사본·과제 지정 새 문서·SUBMISSION.md 중 하나) 6칸, DECISIONS 보완, 과제 중 문서(회고·중간 점검, 있으면), docs/DEFENSE.md 질문 6개, 커밋 [S7] docs: 제출 정리
보고: 원복 안내(복사 명령 또는 "원복할 것 없음") / 점검 목록(항목 · 경로 · 지울지 사람 확인) / 의도가 빈 결정 번호 / 필수 제출물 경로 확인 결과
      / 요구 미확인(check-req.sh verify 출력 한 줄 — 알려진 한계에 옮겼는지)
```
불변 조건: DEFENSE는 정확히 6문항, 답 없음. 미확인·미충족 요구 ID는 모두 제출 문서 "알려진 한계"에 있다. 회고·중간 점검의 사실은 기록에 있는 것만, 느낌은 사람 말 그대로. 제출 문서의 실행 명령은 실제로 띄운 명령 그대로. 과제 원본 파일 diff 0(`check-stage.sh S7` 통과), 복사본마다 원복 명령 한 줄.

## 원칙
1. 한계는 숨기지 않고 제출 문서 "알려진 한계"에 적는다.
2. 질문은 DECISIONS와 실제 코드 위치를 근거로 만든다.

## 금지사항
- DEFENSE에 답을 쓰지 않는다.
- 의도 칸을 추론으로 채우지 않는다. 회고·중간 점검 문서에 사람의 느낌·소감을 지어내지 않는다.
- 사람 확인 없이 파일을 지우지 않는다. 서버를 끄지 않는다.
- 과제 원본 파일을 고치거나 복사본을 원본에 직접 복사하지 않는다 — 복사는 안내만 하고 사람이 한다.

## 확인요청
- 의도 칸이 빈 결정 번호를 한 번에 묻는다. 점검 목록에서 지울 것을 묻는다.

## 인접 스킬
- vs `$fde-verify`: verify는 판정, 이 스킬은 판정 결과를 제출물로 옮긴다.
- vs `$fde-blindspot`: 정리를 시작하기 전에 Cycle 2로 한 번 더 부른다.

## 완료
- 필수 제출 파일이 모두 실제 경로에 있고 최종 커밋이 됐다. 160분이 되면 여기까지로 끝내고 사람에게 넘긴다.
- 자가 검증: STATE 필수 제출물 목록의 경로(복사본이면 `submission/` 경로)가 전부 존재하고, `check-stage.sh S7`이 원본 변경 없이 통과하고, 복사본마다 원복 명령이 보고에 있고, DEFENSE 문항 수가 6이고, 과제 중 문서가 있으면 빈 질문이 없거나 "(미응답)"으로 표시돼 있다.
- 사람에게 상기: 에디터 "저장됨"·충돌 표시 확인 / 160–170분 답 연습 — 지점(파일·함수·결정) → 이유·파급 → 다음 검증·개선, 질문 전제가 구현과 다르면 차이부터 /
  170분에 제출 절차 시작(가이드 권장: 종료 10분 전). 미리보기에 일부 파일만 보일 수 있고 **확정 후 수정 불가**.
