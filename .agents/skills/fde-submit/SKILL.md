# S7 정리·제출 (172–205분, 205–210분 제출 버퍼)

제출 문서는 AI와 함께 써도 불이익이 없다. 단 **판단과 근거, 검증 결과, 남은 한계**가 충실히 담겨야 한다.
제출 후 서술형(210–240분, 문항당 약 5분)은 AI·복붙 금지, 사람이 직접 타이핑한다.
그래서 정리는 190분까지 끝내고, 190–205분은 사람이 DEFENSE 질문에 답을 연습하는 시간으로 비워 둔다.

## 할 일
1. 루트 `README.md`(과제 README를 덮어쓰지 말 것 — 과제가 요구한 파일명이 따로 있으면 그것을 우선) 또는 과제가 지정한 문서에:
   - 무엇을 해결하나(현업 언어 2줄) / 실행 방법(명령 그대로, 포트) / 화면 흐름 / 합의 범위와 제외한 것과 이유 / 검증 결과 요약 / 알려진 한계
2. `docs/DECISIONS.md`에 빠진 결정이 있으면 코드·커밋 로그를 보고 채운다.
   단 **의도** 칸은 코드에서 추론하지 않는다 — 비어 있는 결정 번호를 모아 사람에게 한 번에 묻고 답을 그대로 적는다.
3. 점검 목록만 보고(삭제는 사람이 확인 후): 디버그 출력, 안 쓰는 파일, 비밀값 흔적, 필수 제출 파일 누락.
4. 서술형 예상 질문 6개를 `docs/DEFENSE.md`에 **질문만** 적는다. 형식: "왜 X를 이렇게 했나", "Y가 실패하면 어떻게 되나", "Z를 개선하려면 무엇부터". 답은 쓰지 않는다.
5. 서버는 실행 중인 상태로 둔다.

## 끝
- 묻는다: 의도 칸이 빈 결정 번호(한 번에), 점검 목록에서 지울 것.
- 남긴다: README(또는 과제 지정 문서), DECISIONS 보완, `docs/DEFENSE.md` 질문 6개, 최종 커밋 `[S7] docs: 제출 정리`.
- 완료: 필수 제출 파일이 모두 실제 경로에 있고 최종 커밋이 됐다. 190분이 되면 여기까지로 끝내고 사람에게 넘긴다.
- 사람 몫:
  - 에디터 저장 상태가 모두 "저장됨"인지, 충돌 표시가 없는지.
  - 190–205분 DEFENSE 질문에 내 말로 답 연습. 답 틀: 지점(파일·함수·결정) → 이유·파급 → 다음 검증·개선.
    질문 전제가 구현과 다르면 차이부터 밝힌다.
  - 205분에 제출 절차 시작. 미리보기에 일부 파일만 보일 수 있다. **확정 후에는 수정이 불가능**하므로 필수 제출물 경로를 그 전에 확인한다.
