# 세션 교체

## 기존 세션에서
1. `docs/HANDOFF.md`를 양식대로 덮어쓴다.
   - 목표 한 줄, 실행 방법(명령·포트), **실제로 실행해서 확인한 것**과 **미확인** 구분
   - 내린 결정은 DECISIONS 번호만, 남은 일 순서, 알려진 위험
   - "다음 한 걸음": 새 세션이 첫 명령으로 바로 실행할 수 있게 구체적으로
2. `docs/STATE.md` 현재 단계·작업 목록·기준판(복귀 지점·다음 작업) 갱신.
3. 사람에게 알린다: "새 세션을 열고(Codex `/new`, Claude Code `/clear`) 아래 첫 프롬프트를 입력하세요."

## 새 세션 첫 프롬프트
"AGENTS.md(Claude Code는 CLAUDE.md), docs/HANDOFF.md, docs/STATE.md 순서로 읽고 3줄로 요약해. 다음 한 걸음을 시작하기 전에 내 확인을 기다려."

## 보조 세션 반환
메인을 결정 전용으로 지키기 위해, 조사·디버깅·리뷰를 맡은 보조 세션은 아래 5줄만 돌려준다. 코드는 고치지 않는다.
```
요약: (한 줄)
근거: (실행한 명령·결과, 파일:줄)
선택지: (A / B, 각 한 줄 트레이드오프)
위험: (선택 시 깨질 수 있는 것)
다음 질문: (사람이 정해야 할 것)
```
- 대화 전문·실패한 가설은 메인 문서(DECISIONS·STATE)에 옮기지 않는다. 사람이 채택한 결론만 메인이 반영한다.
- 리뷰는 최대 2회. 2회 뒤에도 남은 지적은 DECISIONS "알려진 약점"으로 넘기고 진행한다.

## 끝
- 묻는다: 확인한 것/미확인을 가를 수 없는 항목(직접 실행했는지 모르면 미확인).
- 남긴다: `docs/HANDOFF.md`, STATE 갱신, 커밋 `[H] docs: handoff`.
- 완료: "다음 한 걸음"이 명령 하나로 시작할 수 있을 만큼 구체적이다.
- 사람 몫: 새 세션 열기와 첫 프롬프트 입력, 보조 세션 결론 중 무엇을 채택할지.
