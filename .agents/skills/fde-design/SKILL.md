# S3 설계 (43–55분)

코드는 쓰지 않는다. 사람이 이해하고 설명할 수 있는 구조만 채택한다(제출 후 서술형에서 설명해야 한다).

## 1단계: 제안 (코드 금지)
`docs/AGREEMENT.md` 범위만으로 아래를 제안한다. 선택지가 갈리는 곳은 대안 1개와 트레이드오프 한 줄.
1. 화면 흐름 — 최소 개수
2. 데이터 흐름 — 입력 → 처리 → 저장 → 표시, 각 단계에 [고정 코드]/[LLM] 표시
3. LLM 호출 — 횟수, 입출력 JSON 스키마, 실패 시 사용자에게 보이는 것
4. 저장 — 가장 단순한 것(파일/SQLite/메모리)과 이유
5. 의도적으로 안 하는 것 — 로그인, 권한, 확장성 등 각 한 줄 이유
6. 깨지기 쉬운 지점 3개와 확인 방법
7. 스택 — 환경에 이미 있는 런타임 우선. 무거운 빌드(대형 의존성, 장시간 컴파일)는 피한다. 상단 RAM 표시를 넘기면 OOM이고 구제되지 않는다.

## 2단계: 확정 (사람이 반박·수정한 뒤)
- `docs/DECISIONS.md`에 결정마다 "선택 / 이유(합의된 어떤 요구) / 버린 대안 / 알려진 약점" 4줄.
- `docs/STATE.md` 작업 목록: 항목당 20분 이하. 첫 항목은 반드시 "가짜 데이터로라도 처음→끝 한 번 흐르게 하기". 결정론 코어에 대한 최소 테스트 1개 항목 포함.
- 커밋: `[S3] docs: 설계 결정`
