# S1 발굴 (8–33분)

## 역할
이 스킬은 담당자의 말을 잃지 않게 정리하고, 아직 비어 있는 것을 채울 다음 질문을 제안한다.
요구는 묻는 만큼만 나온다. 사소하고 구체적인 질문이 좋은 평가를 받는다.
사람이 정하는 것: 담당자에게 실제로 묻는 것, 어떤 질문을 보낼지.

## 입력
사람이 붙여넣은 담당자 대화(여러 번 나눠 들어온다). 첫 호출 때 `references/expertise-extraction.md`를 한 번 읽는다.

## 절차
요청 문장의 *"제가/저희가 ~하는 **방식·기준·순서**"*가 **인터뷰로만 나오는 요구(R-암묵)**이고, 세 층으로 받는다.

| 층 | 받아야 하는 것 | 없으면 |
|---|---|---|
| **L1 기준** | 먼저 보는 것, 좋은 것/아쉬운 것을 가르는 변수 | 지표를 추측해서 만든다 |
| **L2 구조** | 어떤 순서로, 몇 개까지 말하는가 | 출력 스키마·화면 배치의 근거가 없다 |
| **L3 어휘** | 실제로 쓰는 **문장 원문** | LLM이 일반론을 쓴다 |

세 층과 별도로 **요구 칸 3개**(목표(왜) / 성공 판단 / 상쇄)를 추적한다 — "무엇을 왜 만드나"다. 비면 S2가 한 줄 명세·
성공 기준·범위 자르기를 추측으로 쓴다. 질문: `references/expertise-extraction.md` §2 [왜]·[성공]·[거절].

1. `docs/INTERVIEW.md` 양식대로 정리한다. 담당자가 한 말은 **인용**, 너의 해석은 **해석**. L1·L2·L3과 요구 칸은 반드시 인용으로 남긴다.
2. 구현 방향을 바꿀 수 있는 질문 3개를 우선순위대로 제안한다. 비어 있는 층이 1순위, 비어 있는 요구 칸이 2순위.
   질문 순서: `references/question-bank.md`, 3층 질문: `references/expertise-extraction.md`.
3. **의미 후보 (제안하는 질문에 담당자 용어가 2가지 이상으로 읽힐 때만)**: 열린 질문 대신 후보 2~3개를 만들어 "이 중 어느 쪽에
   가까운가요, 또는 둘 다 아닌가요?"로 묻는다. 한 번의 답으로 끝나 왕복을 줄인다. 모호하지 않은 용어에는 쓰지 않는다
   (매번 쓰면 질문이 길어지고 답변 선택지에 담당자가 끌려간다).

## 출력
```text
파일: docs/INTERVIEW.md — 대화 기록 표(# / 내 질문 / 팀장 답(인용) / 내 해석), 정리(요구 칸·L1·L2·L3 인용 표시), 남은 질문
보고:
층 상태: L1 <확보 n개|empty> / L2 <확보 n개|empty> / L3 <확보 n개|empty>
요구 칸: 목표 <확보|empty> / 성공 판단 <확보|empty> / 상쇄 <확보|empty>
다음 질문:
1. <질문> — 채우려는 층·칸 (<용어가 모호하면> 후보: A/B[/둘 다 아님])
2. <질문> — …
3. <질문> — …
```
불변 조건: 질문은 정확히 3개. 비어 있는 층은 `empty`로 쓴다. 인용 칸에는 담당자 원문만 들어간다. 의미 후보는 모호한 용어에만, 질문당 최대 3개.

## 원칙
1. 질문은 장면·기준·빈도를 묻는다. 한 번에 한 질문으로 보낼 수 있는 문장으로 쓴다.
2. 제안하는 3개는 **후보**다. 담당자에게는 한 번에 질문 **하나만** 보내고 답을 받은 뒤 다음 질문을 보낸다 —
   세 개를 한꺼번에 묻지 않는다(담당자가 한꺼번에 여러 걸 받으면 일부만 답하거나 거꾸로 되묻는다).
3. 담당자 어휘를 바꾸지 않는다. 다듬은 표현은 해석 칸에만.

## 금지사항
- 해법 단어(AI, 자동화, 기능, 화면, API)를 질문에 넣지 않는다.
- 담당자가 하지 않은 말을 인용 칸에 넣지 않는다.
- 구현 아이디어·지표·스키마를 제안하지 않는다(S3의 일).
- 모호하지 않은 용어에 의미 후보를 붙이지 않는다. 후보가 담당자의 답을 유도하는 방향으로 치우치지 않게 쓴다.

## 확인요청
- 붙여넣은 대화에서 누가 한 말인지 불분명하면 인용으로 넣기 전에 묻는다.

## 예시
### 입력
```
나: 선수에게 의견 주실 때 어떤 순서로 말씀하세요?
팀장: 잘한 거 하나 먼저요. 그다음 고칠 거 하나. 여러 개 말하면 다 놓쳐요.
```
### 출력
```text
INTERVIEW 대화 기록: | 3 | 의견 주는 순서 | "잘한 거 하나 먼저요. 그다음 고칠 거 하나. 여러 개 말하면 다 놓쳐요." | 칭찬 1 → 개선 1, 개선점은 한 번에 하나 |
INTERVIEW 정리: L2 순서·개수 (인용): "잘한 거 하나 먼저요. 그다음 고칠 거 하나."
층 상태: L1 empty / L2 확보 1개 / L3 empty
요구 칸: 목표 확보 / 성공 판단 empty / 상쇄 empty
다음 질문:
1. 좋은 답변과 아쉬운 답변을 들으면 가장 먼저 뭐가 보이세요? — L1
2. 고칠 점을 말씀하실 때 선수에게 실제로 하신 말을 문장 그대로 기억하세요? — L3
3. "코칭 방식"이 — (A) 피드백을 주는 순서·말투에 가깝나요, (B) 연습 스케줄을 짜는 방식에 가깝나요, 둘 다 아닌가요? — L2, 용어 모호(의미 후보)
```

## 인접 스킬
- 다음: `$fde-agreement`가 INTERVIEW를 읽어 범위를 정한다. 남은 질문은 합의문 "가정"으로 넘어간다.
- **병렬(선택)**: 답을 받는 즉시 다음 질문을 담당자에게 보내고, 지금까지 받은 답의 표·정리 반영은 **보조 세션**(같은 작업
  폴더에서 연 두 번째 Codex)에 "지금까지 받은 답을 `docs/INTERVIEW.md`에 반영해 줘"로 맡길 수 있다. 보조가 그 파일을
  직접 쓰므로 메인은 결과를 다시 받아 적지 않고 다음 질문을 계속 준비한다. **이 파일은 보조만 쓴다** — 같은 호출 구간에
  메인이 동시에 고치지 않는다(파일 충돌 방지). 급하지 않으면 안 써도 된다.

## 완료
- **L1·L2·L3이 각각 인용 1개 이상**, 장면을 한 번 이상 들었다. 요구 칸은 채우려 애쓰되 완료 조건은 아니다 — 33분이 되면
  무조건 종료하고, 빈 층·빈 요구 칸은 합의문 "가정"에 "L2 미확보, 임시로 ○○ 순서 사용" / "성공 판단 미확보 → 합의 확인
  메시지에서 묻는다"처럼 **무엇을 추측했는지** 넘긴다. 커밋 `[S1] docs: 현업 인터뷰 정리`.
- 자가 검증: 정리의 L1·L2·L3 줄마다 대화 기록 표의 인용 원문이 있다.
