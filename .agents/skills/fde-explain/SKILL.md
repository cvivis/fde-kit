# 이해 맥락 (선택 — 필수 단계 아님, 언제든)

## 역할
이 스킬은 사람이 지금까지 만든 것을 **자기 말로 설명할 수 있게** 맥락을 심는다(담당자 보고, S7 정리, 제출 후 서술형에서 필요하다).
부르지 않으면 아무 일도 하지 않는다. 다른 단계의 진행·승인을 바꾸지 않는다.
사람이 정하는 것: 무엇을 알고 싶은지(전체 / 결정 하나 / 로직 / 개념 하나), 더 깊게 볼 곳.

## 입력
필요한 절만 읽는다. 전체 코드·문서를 처음부터 다시 읽지 않는다.
- 전체: `docs/STATE.md` 기준판·작업 목록, `docs/DECISIONS.md` 결정마다 "선택"·"이유" 칸, `docs/LOGIC.md` 결정·단계 표·손 예시, `git log --oneline -10`
- 결정 하나: 그 결정 ID의 5줄과 이유 칸이 가리키는 AGREEMENT·INTERVIEW 줄
- 로직: LOGIC 단계 표·손 예시, 단계 함수가 있는 파일만(`grep`으로 찾는다)
- 개념 하나: 사람이 물은 용어와 그 용어가 나오는 이 과제의 파일 한 곳

## 절차
1. 사람이 범위를 말하지 않았으면 "전체"로 한다. 범위 밖은 읽지 않는다.
2. 문서와 코드가 다르면 **차이를 먼저** 말한다(어느 쪽이 실제 동작인지, 파일:줄).
3. 아래 출력 형식으로 40줄 안에 쓴다. 쉬운 말, 이 과제의 실제 이름(파일·함수·결정 ID·데이터 값)을 쓴다.
4. 끝에 "더 깊게 볼 곳" 한 줄을 묻는다. 사람이 고르면 그 부분만 같은 형식으로 한 번 더 푼다.

## 출력
```text
지금 만든 것: <누가 무엇을 하게 되나 한 줄>
흐름: <입력> → <처리 단계(고정 코드|LLM), 파일:함수> → <결과 화면>
결정: D<n> <무엇을> — 왜(이유 칸 원문) / 바꾸면 깨지는 것   (최대 3개)
로직 따라가기: <손 예시 1건을 단계 순서대로, 실제 값>
어디를 보면 되나: <바꾸고 싶은 것> → <파일:함수>   (최대 3줄)
예상 질문: <질문>  — 근거 위치   (3개, 답은 쓰지 않는다)
모르는 것: <문서·코드에 없어 설명 못 한 것>
```
개념 하나를 물으면: `뜻(한 줄) / 이 과제에서는(파일:줄) / 비슷해서 헷갈리는 것` 3줄.
불변 조건: 파일을 만들거나 고치지 않는다. 설명은 문서·코드에 있는 것만. 의도는 DECISIONS 의도 칸 원문이 있을 때만 인용하고, 없으면 "의도 미기록"이라 쓴다.

## 원칙
1. 사람이 서술형·담당자 질문에 바로 쓸 수 있게 지점(파일·함수·결정)부터 말한다.
2. 짧게. 한 번에 다 설명하지 않고, 사람이 고른 곳만 깊게 간다.

## 금지사항
- 코드·문서를 고치지 않는다. 진행 중인 작업 목록·승인 범위를 바꾸지 않는다.
- 문서·코드에 없는 이유나 사람의 의도를 지어내지 않는다.
- 서술형 답을 대신 써 주지 않는다(예상 질문까지만).

## 확인요청
- 무엇을 알고 싶은지 모호하면 "전체 / 결정 하나 / 로직 / 개념" 중 하나를 고르게 한 번만 묻는다.

## 인접 스킬
- vs `$fde-handoff`: handoff는 새 세션에 상태를 넘기고, 이 스킬은 사람에게 맥락을 넘긴다.
- vs `$fde-submit`: submit은 DEFENSE에 질문을 쓰고, 이 스킬은 아무것도 쓰지 않고 설명만 한다.

## 완료
- 출력 형식대로 40줄 안에 답했고, 파일 변경이 없다(`git status`가 그대로).
- 자가 검증: 설명에 나온 파일·함수·결정 ID가 실제로 있다.
