# S4 E2E v0 (50–100분) / S5 심화 (100–130분)

## 역할
승인된 작업 목록을 실행되는 상태로 만든다. 기본은 **연속 실행**: 한 항목의 완료 조건을 확인하고 기록·커밋한 뒤 다음 항목으로 간다.
사람이 "이번 항목만", "다음 항목 하나만"이라고 하면 하나 후 멈춘다. 실행 방식을 STATE 기준판에 적는다.
사람이 정하는 것: 범위·설계 변경, 직접 발화·청취 같은 수동 확인, S5 개선안 선택.

## 입력
`docs/STATE.md` 기준판·작업 목록·실패 기록, `docs/DECISIONS.md`의 이번 항목 관련 결정만.
성공 기준은 `docs/AGREEMENT.md` 해당 번호만 읽는다. 이전 항목의 코드·문서를 통째로 다시 읽지 않는다.
OpenAI·녹음이 필요할 때만 `references/openai-patterns.md` 해당 패턴을 읽는다.
작업 목록이 없거나 승인되지 않았으면 구현하지 않고 범위·설계 확인을 받는다. 첫 항목 전에 한 번
`bash .agents/skills/fde-start/scripts/check-stage.sh S4`를 실행한다. 실패 시 빈 칸을 보여 주고 멈춘다.

## 절차
1. 다음 미완료 항목 하나를 구현한다. 필요한 코드·테스트만 수정하고 합의 밖 기능을 추가하지 않는다.
2. **첫 항목은 실제 입력 → 실제 처리 → 결과의 최소 E2E**다. 모델은 S0에서 확인한 목록에서 고른다.
   API 환경이 있으면 실제 LLM·STT 등 핵심 외부 경로를 첫 항목에서 확인하고 성공·실패를 VERIFY에 남긴다.
   음성 흐름이면 짧은 녹음의 STT 결과를 코칭 입력으로 잇는다. 텍스트 대체 경로의 성공으로 음성 성공을 대신하지 않는다.
   환경이 없거나 연결이 막히면 모의로 대체할 범위를 사람에게 한 번 확인받고 STATE "모의 상태"에 기능·이유를 적는다.
   이미 승인된 모의 범위는 다시 묻지 않는다. 실제 경로는 별도 미완료 항목으로 남기고 모의를 실제 완료로 표시하지 않는다.
3. 서버는 **0.0.0.0**, 포트는 지문·설계를 따른다. 기존 서버를 재사용하고 실행 명령·PORT·경로·기대 결과를 알린다.
4. 완료 조건을 직접 실행해 확인한다. 바뀐 동작에 필요한 테스트만 실행한다. 관련 없는 전체 검사를 항목마다 반복하지 않는다.
   사람이 해야 하는 발화·청취는 미확인으로 남긴다. 그 확인에 의존하지 않는 다음 항목은 계속할 수 있다.
5. VERIFY 표에 항목당 한 행: 시각·항목·명령·관측 결과(실제/모의/미확인). STATE 작업 체크와 다음 작업을 갱신한다.
   코드·증거를 의미 단위로 커밋 `[S4] feat: …`(S5는 `[S5]`). 이어 STATE 복귀 지점에 그 SHA를 적고 다음 항목 커밋에 포함한다.
   마지막에는 STATE 갱신을 따로 커밋할 수 있다. 복귀 SHA는 **실행 확인한 구현 커밋**이며 문서 전용 HEAD와 달라도 된다.
6. 연속 실행이면 다음 항목으로 간다. 첫 E2E·막힘은 짧게 보고하고, 사람의 추가 판단이 필요하지 않으면 응답을 기다리지 않는다.
   단일 항목 모드, 승인 목록 완료, 확인요청 조건, 130분 도달 중 하나면 멈추고 현재 상태·다음 일을 보고한다.

### 막혔을 때
- 실패를 STATE "실패 기록"에 `<항목> · <증상> · 1회`로 적고 같은 증상은 2회로 올린다. 2회면 반복 수정을 멈추고
  원인 가설 3개와 확인 방법을 보고한다. 필요할 때만 보조 세션에 조사시켜 채택한 결론을 받는다.
- OpenAI 실패는 환경 확인부터. 같은 모델 호출을 성공할 때까지 반복하지 않는다.
- 한 항목 15분 초과면 원인·남은 일을 보고한다. 범위·완료 조건을 바꿀 필요가 있으면 확인받고, 독립적인 승인 항목은 진행할 수 있다.
  실패한 변경을 숨긴 채 다음 항목과 섞어 커밋하지 않는다. stash 등 작업 이동은 사람 확인 후에 한다.

### S5 심화 (E2E v0이 된 뒤에만)
기능을 늘리지 않는다. 성공 기준의 부족한 지점과 개선안 2개를 비교해 한 번에 선택받는다.
이미 승인된 개선 항목은 추가 승인 없이 항목별로 진행하고 VERIFY에 전/후를 남긴다.

## 출력
```text
보고: 실행 방식 <연속|단일> / 완료 항목 / 확인 <명령·PORT·경로·관측 결과> / 남은 일·위험
파일: 코드·필요한 테스트, VERIFY 항목별 한 행, 의미 단위 [S4]|[S5] 커밋, STATE 체크·복귀 SHA·다음 작업
```
불변 조건: 항목별 구현·증거·커밋을 남긴다. 연속 실행은 전체를 한 덩어리로 구현·커밋하는 허가가 아니다.
실행하지 않은 결과와 모의 성공을 실제 성공으로 기록하지 않는다.

## 원칙
1. 판정·계산·저장은 고정 코드 + 최소 테스트, LLM은 해석·문장과 JSON 스키마 + 파싱 실패 경로.
2. 음성 입력에는 텍스트 대체 경로를 둔다. 첫 E2E의 실제 연결 확인이 부가 화면·기록 꾸미기보다 먼저다.
3. DECISIONS는 선택이 바뀔 때만 고친다. 사람의 변경 이유는 "내가 바꾼 제안"에 원문으로 남긴다.

## 금지사항
- 승인 목록·AGREEMENT 밖 기능, 미승인 설계 변경, 완료 조건의 임의 완화.
- 실행 확인·기록·커밋을 생략한 여러 항목 통째 구현.
- `git reset --hard`, 키·URL 값의 코드·로그 기록.

## 확인요청
- 범위·설계를 바꿔야 할 때, 모의 대체 범위를 처음 정할 때, 무거운 설치 전, 같은 실패 2번째.
- 사람만 확인 가능한 조건이 다음 항목의 전제일 때. 이미 승인된 일반 구현·다음 항목에는 재승인을 요구하지 않는다.

## 인접 스킬
- `$fde-verify`: 별도 세션에서 성공 기준 전체를 검증한다. 구현 항목별 확인을 대신하지 않는다.
- 100분은 맥락 점검 시점이다. 결정 재질문·설명 반복 등 문제가 있을 때만 `$fde-handoff`한다.

## 완료
- 단일 모드는 항목 하나 후, 연속 모드는 승인 목록 완료·확인요청·130분 중 먼저 온 시점에 종료한다.
- 자가 검증: 완료 표시마다 VERIFY 실행 증거가 있고, 복귀 SHA가 그 구현 커밋을 가리킨다. 문서 전용 HEAD와의 차이는 정상이다.
- S6 진입은 별도 세션에 넘긴다. 130분에 미완료 항목은 그대로 표시하고 STATE 진행 측정 한 행을 남긴다.
