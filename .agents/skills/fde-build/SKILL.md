# S4 E2E v0 (50–100분) / S5 심화 (100–130분)

## 역할
**호출마다 항목 하나, 끝나면 멈춘다.** 작업 목록에 항목이 여러 개 남아 있어도 이번 호출에서는 하나만 코드로 만들고, 나머지는
건드리지 않은 채로 사람에게 확인받는다 — 이 문장이 아래 절차·금지사항·완료 조건에 또 나오는 건 중복이 아니라 실제로 자주
안 지켜지는 규칙이기 때문이다.
이 스킬은 작업 목록 항목 하나를 실행되는 상태로 만들고 증거를 남긴다.
사람이 정하는 것: 화면에서 직접 눌러 확인, 구현 방향 변경과 그 이유, S5 개선안 고르기.

## 입력
`docs/STATE.md` 작업 목록의 다음 항목 하나(완료 조건 포함), `docs/DECISIONS.md`. OpenAI·녹음은 `references/openai-patterns.md`.
**작업 목록이 비어 있으면 구현하지 않는다** — S3(`$fde-design`)로 돌려보낸다. S4 첫 항목 전에 한 번
`bash .agents/skills/fde-start/scripts/check-stage.sh S4`를 실행하고, 실패하면 빈 칸을 보여 주고 멈춘다.

## 절차
1. **다음 항목 하나만** 구현한다. 다른 파일은 건드리지 않는다.
2. DECISIONS를 따른다. 벗어나야 하면 구현 전에 멈추고 이유를 말한다.
   사람이 방향을 바꾸면(네 방식 거절, 다른 방식 지시) DECISIONS "내가 바꾼 제안"에 한 줄 — 이유는 사람 말 그대로.
3. 모델명은 S0에서 확인한 목록에서 고른다.
4. 서버는 **0.0.0.0** 바인딩, 포트는 고정값으로 README와 보고에 적는다.
5. 사람이 확인할 방법을 준다: 실행 명령, Browser 도구에 넣을 PORT와 경로, 기대 결과(= 항목의 **완료 조건**). 완료 조건이 보이면 그 항목은 끝이다 — 더 다듬지 않는다.
6. 확인되면 VERIFY에 명령·결과 한 줄, 커밋 `[S4] feat: …`(S5는 `[S5]`).
7. STATE 기준판 **복귀 지점**(방금 커밋 SHA와 그때 되는 것)과 **다음 작업**을 갱신한다.

### 막혔을 때
- 실패하면 STATE "실패 기록"에 `<항목> · <증상 한 줄> · 1회`를 적는다. 같은 증상 줄이 이미 있으면 2회로 올리고
  **고치지 말고** 원인 가설 3개와 확인 방법만. 확인은 보조 세션에서, 채택한 결론만 받는다. 해결되면 그 줄을 지운다.
  (횟수를 기억에 맡기지 않는다 — 세션이 바뀌면 잊는다.)
- OpenAI 호출 실패 → `python3 .agents/skills/fde-start/scripts/check-openai.py`부터.
- 한 항목 15분 초과 → 더 쪼개거나 가짜 데이터로 대체하고 다음 항목. 상태가 망가졌으면 사람 확인 후 `git stash`로 치우고 복귀 지점에서 다시.

### S5 심화 (E2E v0이 된 뒤에만)
기능을 늘리지 않는다. 성공 기준 하나를 골라 어디서 못 채우는지(파일·함수) 짚고, 개선안 2개 비교 후 사람이 고른 것만 구현. 전/후를 VERIFY에.

## 출력
```text
보고: 한 일 / 바꾼 파일 / 확인: <실행 명령> · PORT <n> · 경로 <path> · 기대 결과 <한 줄> / 남은 일·위험
파일: 코드, docs/VERIFY.md 한 줄(시각 · 확인한 것 · 명령 · 결과), 커밋 [S4]|[S5], STATE 기준판 복귀 지점·다음 작업
```
불변 조건: 한 번 호출에 항목 하나. VERIFY 결과는 실제 실행한 것만(추정이면 "추정"이라고 쓴다).

## 원칙
1. 결정론 코어(점수·판정·계산·저장)는 고정 코드 + 최소 테스트. 테스트 실행 결과도 평가 자료다.
2. LLM 응답은 JSON 스키마, 파싱 실패 시 화면에 보일 문구까지.
3. 음성 입력 과제는 **텍스트 입력 대체 경로**를 같이 둔다(미리보기에서 마이크가 막힐 수 있다).

## 금지사항
- 다음 항목을 묻지 않고 이어서 구현하지 않는다.
- "합의된 어떤 요구 때문인가" 한 줄로 답 못 하는 방어 로직·추상화를 넣지 않는다.
- `git reset --hard`를 쓰지 않는다. 키·URL 값을 코드·로그에 넣지 않는다.

## 확인요청
- DECISIONS를 벗어나야 할 때, 무거운 설치 전, 같은 실패 2번째(STATE "실패 기록"이 2회).

## 인접 스킬
- vs `$fde-verify`: 이 스킬은 항목별 확인, verify는 별도 세션에서 성공 기준 전체를 처음 보는 눈으로.
- 약 100분 또는 맥락이 무거워지면 `$fde-handoff`.

## 완료
- 항목 하나가 실행으로 확인되고 기록됐다 — 여기서 멈춘다. 130분이 되면 진행 중 항목을 멈추고 S6.
- 자가 검증: 기준판 복귀 지점 SHA가 `git log -1`과 같고, VERIFY 마지막 줄이 이번 항목이다.
