# S0 착수

## 역할
이 스킬은 환경과 과제를 정확히 파악해 이후 단계가 읽을 기준 문서를 만든다.
사람이 정하는 것: 과제 지문 정독, 열린 결정 중 무엇을 담당자에게 물을지.

## 입력
작업 폴더 루트의 과제 README(루트에 없으면 `find . -iname "README*"`)와 함께 받은 파일(기획서·RFP·데이터·이미지 등),
사람이 대화창에 붙여 넣은 문제 글·공고. 문제는 입력 종류만 다를 뿐 이후 과정은 같다 — 입력을 빠짐없이 모으는 것이 이 단계의 일이다.

## 절차
1. 작업 폴더 루트에서 `bash .agents/skills/fde-start/scripts/init-docs.sh` 실행. 양식보다 먼저 과제 원본 파일 목록·해시를
   `docs/TASK-ORIGINALS.sha256`에 남긴다 — 이 파일들은 끝까지 고치지 않는다(AGENTS.md 원칙 11).
1-1. **파일이 아닌 입력 보존(KR-178)**: 사람이 문제 글·공고·대화를 붙여 넣었거나 화면·연결 도구로 받았으면 `docs/inputs/NN-<짧은 이름>.md`에
   받은 글을 **원문 그대로**(요약·정리·맞춤법 수정 없이) 저장하고 첫 줄에 `<!-- 출처: 붙여 넣음 | 화면 <이름> | 도구 <이름> -->`를 둔다.
   저장한 뒤 `init-docs.sh`를 다시 돌리면 새 입력이 원본 목록에 더해진다(이후 고치지 않는다). 과제 중에 새 입력(다음 단계 문제·추가 자료)이 오면
   같은 방법으로 더하고 STATE "입력 목록"에 행을 붙인다.
2. README와 `docs/inputs/`를 읽고 `docs/STATE.md` "과제 요약"을 채운다.
   - 현업 요청 원문은 그대로 인용
   - **필수 제출물·필수 파일명·필수 문서**(계획 문서, 협업 기록 등)를 README 원문 그대로 목록으로
   - 필수 제출물이 **이미 있는 원본 파일**(예: 과제 README에 실행 방법을 채우라는 요구)이면 STATE "제출 복사본"에
     `submission/<같은 경로> ← <원본 경로>`로 적는다. 복사본은 그 내용을 처음 쓰는 단계가 `cp`로 만든다. 원본은 고치지 않는다
   - **과제 중에 쓰는 문서**(회고·중간 점검처럼 과제 진행 자체를 묻는 md — 이름·질문·형식은 과제마다 다르다)가 지문·작업 폴더에 있으면
     파일명·질문 원문·양식·작성 시점을 그대로 목록에 따로 적는다. 키트의 예시 질문으로 바꾸지 않고 과제가 준 양식을 따른다.
     작성 시점이 지문에 없으면 "중간 점검 성격 = 세션 교체 때, 회고 성격 = S7"로 둔다
   - 필수 요구 / 열린 결정(정해지지 않은 것) 구분
   - 실행 환경 제약(포트, 언어, OpenAI 사용 방식)
3. 환경 확인 (값은 출력하지 않는다):
   - 지문·기존 프로젝트가 쓰는 런타임 버전만 확인한다. 스택이 없으면 사용 가능한 가벼운 런타임 하나를 확인한다.
   - OpenAI 환경변수 존재를 먼저 확인한다. 키가 없으면 모델 목록은 "미확인 — 환경 없음"으로 남긴다.
   - 키와 SDK가 이미 있으면 `check-openai.py` 또는 `check-openai.mjs` 중 환경에 맞는 하나만 실행한다.
     목록 조회만을 위한 SDK 설치는 하지 않는다. SDK가 없거나 조회가 막히면 S4 실제 연결 항목으로 넘긴다.
4. STATE 기준판의 "목표 한 줄"(현업 요청 요약)과 "제약"(포트·런타임·사용 가능 모델)을 채운다.
   - **입력 목록(KR-166)**: STATE `## 입력 목록` 표에 입력마다 한 행(종류·경로·받은 방법)을 적고, 기준판 `- 입력:` 줄에 종류별 개수를 쓴다.
     종류는 지문 / 대화 / 기획서·RFP / 데이터 파일 / 이미지·도면 / 기타. 과제 유형으로 흐름을 나누지 않는다 — 모든 입력이 S1 요구 도출·조사의 대상이다.
     대화 입력(붙여 넣은 대화, 또는 지문이 담당자·현업 파트너와 대화하라고 함)이 있으면 S1에서 `$fde-interview`로 먼저 정리한다.
   - **외부 조사**: 대회 규정과 지금 도구에 웹 검색이 있는지로 `- 외부 조사: 가능` 또는 `- 외부 조사: 불가` — 근거 한 줄. 모르면 `불가`로 두고 보고에 적는다.
4-1. **지문 요구 → `docs/REQ-TASK.md`**: 지문이 지키라고 한 것(기능·반드시·점수·목표·제출)을 한 행씩 T-01…로, 요구 칸은 지문 원문 그대로.
   우선(필수/권장)은 지문 표현으로 가르고, 범위는 기본 `이번`(뺄 이유가 지문에 있을 때만 `제외 — 이유`). 설계 연결·구현 확인 칸은 비워 둔다.
   `bash .agents/skills/fde-start/scripts/check-req.sh count`로 개수 줄과 STATE 기준판 "요구" 줄을 고친다(스크립트가 쓴다 — 손으로 옮기지 않는다).
4-2. `docs/INTERVIEW.md` "요구 체크리스트"에서 지문·환경으로 답이 있는 칸만 `값 — 지문`으로 채운다(주로 G1~G4, 지문에 있으면
   A5·B1·H1). 지문에 없는 칸은 비워 둔다 — 지어내지 않는다. 기획 칸(P)은 S1에서 담당자에게 묻는다.
5. 첫 커밋: `[S0] chore: 작업 문서 준비 및 과제 요약` (키트 출처 URL을 커밋 본문에 적는다)

## 출력
```text
파일: docs/ 양식 11종, docs/inputs/(파일이 아닌 입력 원문, 있으면), docs/TASK-ORIGINALS.sha256(과제 원본·입력 원문 목록·해시), .gitignore, docs/STATE.md(과제 요약·입력 목록·기준판 목표 한 줄·제약·입력·외부 조사·요구), docs/REQ-TASK.md(T-ID, 개수 줄), docs/INTERVIEW.md 요구 체크리스트(지문 칸만), 커밋 [S0]
보고: 입력: <종류별 개수 · 경로> / 외부 조사: <가능|불가> / 요구: <check-req.sh count 출력 한 줄>
  필수 제출물: <README 원문 목록> / 제출 복사본: <없음 또는 submission/경로 ← 원본> / 열린 결정: <3개 이내> / 놓치기 쉬운 제약: <3개>
  다음: 대화 입력이 있으면 → 대화 정리($fde-interview) 뒤 조사($fde-research), 질문 순서 미리보기(지도→장면→기준→현재 우회→정량→사용자/환경→성공→경계→상쇄→예외 처리→기획 체크리스트 빈 칸, 한 번에 하나씩)
        대화 입력이 없으면 → 조사($fde-research): 입력에서 요구·사실을 뽑고 조사 결과를 제시해 사람의 검수·판단을 받는다
체크리스트: 지문으로 채움 <ID 목록> / S1 기본 질문(기획) P4 P5 P6 P7 P11 P12 P14 P16 P17 / 개발 칸은 선택 — 묻고 싶은 칸 ID를 S1에서 말하면 질문으로 만든다
```
불변 조건: 필수 제출물은 README 원문 표현 그대로. OpenAI는 "설정됨/없음"과 모델 목록만 적는다. 입력 목록에 작업 폴더의 과제 파일과 `docs/inputs/` 파일이 모두 있고, 붙여 넣은 글은 원문 그대로다.
REQ-TASK 요구 칸은 지문 원문이고 행이 1개 이상이다(`check-req.sh count` exit 0).

## 원칙
1. README에 적힌 것과 내 해석을 구분해 적는다.
2. 이미 있는 과제 파일은 덮어쓰지도 덧붙이지도 않는다(`init-docs.sh`가 기존 파일을 건너뛰고 원본 해시를 남긴다).

## 금지사항
- 코드·앱 파일을 만들지 않는다.
- `OPENAI_API_KEY`·`OPENAI_BASE_URL` 값을 출력·기록하지 않는다.
- 담당자 인터뷰를 대신 시작하지 않는다.
- 붙여 넣은 입력을 요약·수정해 저장하지 않는다.

## 확인요청
- README가 여러 개이거나 필수 제출물이 모호하면 어느 것이 과제 지문인지 묻는다.
- 대화 상대(담당자)가 있는지 애매하면(예: "현장 의견을 반영"만 있고 대화 상대가 없다) 묻는다 — S1에서 `$fde-interview`를 부를지가 여기에 달렸다.
- 받은 입력이 더 있는지(첨부 파일·화면에만 있는 글) 모르면 묻는다.

## 인접 스킬
- 다음: 대화 입력이 있으면 `$fde-interview` → `$fde-research`, 없으면 `$fde-research`. 이 스킬의 STATE 과제 요약·REQ-TASK가 S1의 출발점이 된다.

## 완료
- 필수 제출물 목록과 OpenAI 확인 결과가 STATE에 있다. 확인하지 못한 것은 STATE "막힌 것"으로 넘기고 종료.
- STATE 진행 측정에 시작·S0 종료 시각과 확인 가능한 토큰을 남긴다. 없어도 추측해 만들지 않는다.
- 자가 검증: `ls docs`에 11종과 `TASK-ORIGINALS.sha256`이 있고, STATE 기준판 "목표 한 줄"·"제약"·"입력"·"외부 조사"가 비어 있지 않고 "입력 목록"에 1행 이상 있다.
  `check-req.sh count`가 exit 0이다. 요구 체크리스트에서 `— 지문`이 붙은 칸은 지문에 같은 내용이 있다.
